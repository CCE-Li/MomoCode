# Testing

横切所有模块的测试策略层：定义单元、集成、E2E 与回归测试的规范与门禁。

## 职责范围

- 单元测试、集成测试、E2E 测试策略。
- 回归测试与质量门禁规则。
- 测试结构、命名与用例覆盖要求。

## 触发时机

- 编写或规划测试。
- 搭建或调整测试框架与结构。
- 制定回归覆盖或质量门禁规则。

## 工作流程

1. 按模块确定测试层级（单元 / 集成 / E2E）。
2. 定义测试结构与命名规范。
3. 制定用例覆盖要求。
4. 定义 E2E 关键路径。
5. 制定回归门禁规则（何时必须回归、通过标准）。

## 边界与禁止

- 不定义业务规则、不实现业务代码。
- 测试对象覆盖 `product-design`、`oj-integration`、`algorithm-taxonomy`、`spaced-repetition`、`code-template-training`、`adaptive-learning`、`coding-performance` 对应的模块。
- 不臆造未确认的测试工具或框架，须有确认来源或标 `TODO(确认来源)`。

## 输出物

- 测试策略。
- 用例规范。
- 回归门禁规则。

## 反虚构约定

测试框架、工具与外部服务的真实能力在无确认来源前一律不写死；不确定处标注 `TODO(确认来源)`。

## references 使用

当测试规范或门禁细则较长时，放入本 Skill 的 `references/`（如 `references/test-strategy.md`），并在正文用相对路径引用。

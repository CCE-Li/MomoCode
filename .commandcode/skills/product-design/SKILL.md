# Product Design

MomoCode 是面向算法竞赛（Codeforces / 洛谷 / AtCoder）的个性化算法训练平台。本 Skill 负责产品层的“做什么、为什么做、怎么用”。

## 职责范围

- 产品定位、目标用户与使用场景。
- 需求分析与拆解（用户故事、验收标准）。
- 功能设计与范围划分。
- 用户流程与交互（UX）设计。

## 触发时机

- 需要梳理产品方向或目标用户。
- 编写或更新需求文档（PRD）。
- 拆解、评估某个产品功能。
- 设计用户流程、交互或评估用户体验。

## 工作流程

1. 明确目标用户与核心场景；无法确定时先提问，不假设。
2. 将需求拆为用户故事与可验证的验收标准。
3. 定义功能范围与明确的“不做”边界。
4. 设计主流程、异常流程与关键交互。
5. 标注该需求依赖的领域 Skill（见下），不在本 Skill 细化领域细节。
6. 输出需求文档，并列出待确认项。

## 边界与禁止

- 只决定“做什么 / 为何做 / 怎么用”，不编写业务实现代码。
- 算法分类与标签 → `algorithm-taxonomy`；OJ 接入 → `oj-integration`；复习调度 → `spaced-repetition`；训练计划与难度 → `adaptive-learning`；指标统计 → `coding-performance`；测试 → `testing`。
- 不臆造未确认的功能依赖或外部能力。

## 输出物

- 需求文档（PRD）/ 功能清单。
- 用户流程与交互说明。
- 验收标准与待确认清单。

## 反虚构约定

外部 OJ、平台或库的真实字段、端点、参数在无确认来源前一律不写死；不确定处标注 `TODO(确认来源)`。

## references 使用

当规格较长（完整 PRD、流程细则）时，将细节放入本 Skill 的 `references/`（如 `references/prd-<feature>.md`），并在正文用相对路径引用；SKILL.md 只保留规则与索引。

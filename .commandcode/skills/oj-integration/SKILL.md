# OJ Integration

以 Adapter 架构接入外部在线判题平台，向平台内部提供统一、归一化的题目与提交数据。

## 职责范围

- 外部 OJ 数据接入（题目、提交及必要的元数据）。
- OJ Adapter 架构与统一内部数据契约。
- 平台差异的归一化与错误处理。
- 接入层的缓存与访问频率策略。

## 触发时机

- 新增或修改某个 OJ 平台的接入。
- 解析题目 / 提交数据，或定义统一数据模型。
- 处理平台差异、字段缺失或错误映射。
- 设计 Adapter 接口或接入契约。

## 工作流程

1. 识别目标平台与所需数据字段；先确认数据来源，不确认不写。
2. 定义与平台无关的统一内部数据模型。
3. 为每个平台实现独立 Adapter，负责“平台数据 → 统一模型”的映射。
4. 归一化字段，覆盖缺失、异常与限流的处理规则。
5. 定义缓存与访问频率策略。
6. 将接入契约文档化，并标注未确认项。

## 边界与禁止

- 只负责“取回并归一化外部数据”，不实现复习、训练或调度逻辑。
- 题目知识点归类 → `algorithm-taxonomy`；复习调度 → `spaced-repetition`；训练决策 → `adaptive-learning`。
- 不猜测平台 API：端点、字段、参数须有确认来源，否则标 `TODO(确认来源)`。
- 不引入未确认的第三方服务或依赖。

## 输出物

- Adapter 契约与接口定义。
- 统一内部数据模型。
- 平台适配与错误处理说明。

## 反虚构约定

外部 OJ、平台或库的真实字段、端点、参数在无确认来源前一律不写死；不确定处标注 `TODO(确认来源)`。

当存在具体的接入契约、字段映射表或平台文档摘要时，放入本 Skill 的 `references/`（如 `references/<platform>-adapter.md`），并在正文用相对路径引用。

# MomoCode 项目上下文（所有阶段必读）

## 项目身份
- 名称：MomoCode
- 形态：Web-first，Desktop-ready
- 定位：算法识别与代码模板肌肉记忆训练平台
- 目标：帮助用户长期记忆算法、识别适用场景、独立复现模板、掌握变体并针对薄弱点纠错。

## 核心闭环
学习算法 → 算法识别 → 模板复现 → 变体/纠错 → OJ 评测 → 记录行为证据 → 技能评估 → FSRS 更新 → 下次复习。

## 四类训练
1. 算法识别：根据题意、数据范围、约束和复杂度判断算法。
2. 模板复现：不看参考代码，独立实现基础模板。
3. 变体复现：完成路径恢复、区间修改等算法变化。
4. 针对性纠错：训练边界、初始化、溢出、越界和逻辑错误。

## 核心业务规则
- Algorithm、Skill、PracticeTask 是不同实体。
- 一个 Algorithm 可以拆成多个独立 Skill。
- 每个用户的每个 Skill 独立维护 FSRS 状态。
- FSRS 负责复习调度，不代表综合技能分数。
- Skill Score 与 FSRS Difficulty 不得混为一谈。
- 一次 AC 不等于掌握；WA 也不一定代表遗忘。
- 记录正确性、独立程度、提示等级、耗时、错误类型和变体表现。
- 不同算法耗时不能直接绝对比较，应考虑任务难度和个人历史基准。
- 自由练习默认不更新 FSRS；用户明确标记为正式复习时才更新。
- 提示等级：0 无提示、1 算法类别、2 核心思想、3 数据结构/状态、4 部分代码、5 完整参考实现。
- 不自行开发判题服务器；通过 OJ 跳转、提交同步或手动关联完成闭环。

## 默认技术方向
- 前端：Vue 3、TypeScript、Vite、Pinia、Vue Router、Monaco Editor、ECharts。
- 后端：Python、FastAPI、SQLAlchemy、Pydantic。
- 数据库：PostgreSQL。
- 缓存/后台任务：Redis；ARQ 或 Celery 二选一，先评估再确定。
- 工程：Docker、GitHub Actions。
- OJ：优先评估 Codeforces，再考虑洛谷和 AtCoder。

## 主要模块
Dashboard、Algorithm Library、Smart Review、Free Practice、Practice Workspace、OJ Integration、Analytics、Settings。

## MVP 候选范围
用户基础认证、算法与技能库、四类训练、训练会话与提示记录、FSRS、自由练习、基础统计、首个 OJ 集成或手动提交关联。

初始算法候选：二分查找、双指针、前缀和、差分、BFS、DFS、Dijkstra、并查集、01 背包、LIS。

## AI 协作规则
1. 先读现有代码和文档，不假设仓库为空。
2. 先分析方案；高影响变更先请求确认。
3. 一次只处理当前阶段，不提前实现后续阶段。
4. 不虚构 API、依赖、字段或平台能力；不确定时先验证。
5. 不擅自扩大范围或替换已确认技术栈。
6. 数据库变更必须有迁移，重要业务逻辑必须有测试。
7. 结束时汇报变更文件、实现内容、真实测试结果、遗留问题和下一步。
8. 发现代码与文档冲突，先列出差异，不要静默覆盖。
9. 对认证、密钥和用户数据采用保守安全默认值。
10. 不声称运行过实际未执行的测试。

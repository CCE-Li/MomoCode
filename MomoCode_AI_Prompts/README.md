# MomoCode AI 开发提示词包

本套提示词用于让 AI 按工程顺序开发 MomoCode。每次只执行一个阶段。

## 使用方法
1. 每次都提供 `00_PROJECT_CONTEXT.md`。
2. 再提供当前阶段的 `prompts/XX_*.md`。
3. 同时提供相关现有代码和已确认文档。
4. 设计阶段先产出文档，负责人确认后再编码。
5. 每阶段结束后更新文档、测试并提交阶段总结。

## 推荐流程

| 阶段 | 提示词 | 交付物 |
|---|---|---|
| 0 | 项目上下文 | 项目统一规则 |
| 1 | 需求与 PRD | `docs/PRD.md` |
| 2 | 系统架构 | `docs/ARCHITECTURE.md` |
| 3 | 数据库设计 | `docs/DATABASE.md` |
| 4 | UI/UX 设计 | `docs/UI_UX.md` |
| 5 | 仓库初始化 | 可运行的项目骨架 |
| 6 | 后端基础设施 | FastAPI、数据库、迁移 |
| 7 | 前端基础设施 | Vue 应用骨架 |
| 8 | 算法内容 | 算法、技能、训练任务种子数据 |
| 9 | 训练引擎 | 四类训练流程 |
| 10 | FSRS | 记忆更新与复习队列 |
| 11 | OJ 集成 | 首个 OJ Adapter |
| 12 | Analytics | 指标、统计 API、图表 |
| 13 | QA | 测试与安全报告 |
| 14 | 部署 | Docker、备份、运维文档 |
| 15 | 发布评审 | MVP 验收报告 |

## 阶段门禁
- PRD、架构、数据库和 UI 文档确认后，才进入完整业务开发。
- 前后端基础设施可运行后，才进入业务模块。
- 训练流程稳定并有测试后，才接入 FSRS。
- FSRS 状态更新可靠后，再接入真实 OJ 同步。
- QA 与部署检查通过后，才发布 MVP。

扩展功能（组队、会员、社交、桌面端）不得阻塞核心训练闭环。
